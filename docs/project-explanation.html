一、项目背景与目标

传统病虫害咨询依赖人工经验，响应慢、覆盖有限。本项目用本地知识库和 RAG 思路，将专业农业知识转化为可交互的问答系统。

解决问题

农户描述作物异常后，系统快速给出可能病虫害、判断依据和防治方向。

核心目标

构建一个能实际运行的农业病虫害智能问答系统，覆盖识别、防治、来源和历史记录。

实现原则

无需外部大模型即可演示核心 RAG 流程，便于离线运行、答辩展示和后续扩展。

二、系统总体架构

系统采用前后端一体的 Java Web 应用，前端负责问答交互，后端负责知识库加载、问题解析、检索排序、回答生成和历史管理。

Web 前端 问题输入、快捷样例、知识库筛选、来源卡片、历史回放。
→
Java 后端服务 JDK HttpServer 提供 API，使用虚拟线程处理请求。
→
本地知识库 TSV 文件保存病虫害名称、症状、规律、传播、防治和预防信息。

三、RAG 问答流程

项目实现的是轻量级本地 RAG：先检索相关知识，再基于检索结果生成回答，并把引用来源返回给前端。

用户自然语言提问 例如“水稻叶片有梭形灰白病斑，穗颈发黑，可能是什么病？”
问题解析与意图识别 识别“症状识别、防治咨询、发生规律、预防建议、综合问答”等意图。
关键词和症状召回 提取作物、病虫害名称、别名、症状词和防治词，并在知识库中加权匹配。
Top-K 来源排序 按名称、别名、作物、症状、防治字段综合打分，选出最相关条目。
生成结构化回答 输出判断依据、发生规律、传播途径、农业防治、化学防治、生物防治和预防建议。

四、核心模块说明

项目按职责拆分为 api、domain、repository、service、util 五类模块，结构清晰，便于维护。

启动入口

AgroQaApplication 初始化知识库、问答服务、历史服务和 HTTP 服务。

接口层

AgroQaServer 提供聊天、历史、知识库和静态页面访问。

领域模型

PestKnowledge、QaResponse、SearchHit 表达核心业务数据。

知识库仓储

PestKnowledgeRepository 从 TSV 文件加载并校验病虫害知识。

检索服务

KnowledgeSearchService 完成关键词召回、权重计算和 Top-K 排序。

问答服务

PestQaService 组织答案、追问建议、无法回答提示和多轮上下文。

六、接口说明

后端 API 简洁，前端和测试都通过这些接口访问系统能力。

POST/api/chat

提交问题，返回答案、意图、置信度、来源和追问建议。

GET/api/history

根据 sessionId 获取当前会话的问答历史。

DELETE/api/history

清空指定 sessionId 的历史记录。

GET/api/knowledge

获取知识库概要，用于前端左侧知识列表。

七、典型问答效果

系统能根据症状命中知识库条目，并给出可追溯的防治建议。

用户问题：
水稻叶片有梭形灰白病斑，穗颈发黑，可能是什么病？

系统回答摘要：
根据你描述的症状，优先怀疑是稻瘟病。

判断依据：
叶片出现梭形或纺锤形病斑，中央灰白、边缘褐色；穗颈发黑易折，严重时形成白穗。

防治方案：
1. 农业防治：选用抗病品种，合理密植，控制氮肥、增施磷钾肥。
2. 化学防治：发病初期可用三环唑、稻瘟灵、春雷霉素等按标签剂量喷雾。
3. 生物防治：可使用枯草芽孢杆菌、春雷霉素等生物源制剂辅助防控。

来源：
稻瘟病 · 粮食作物 · 匹配分 14.3
